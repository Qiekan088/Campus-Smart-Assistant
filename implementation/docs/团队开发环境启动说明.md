# 团队开发环境启动说明

环境版本ENV-0.2。团队共享仓库文件和镜像版本，各自在本机启动独立容器，不共用可写数据库。业务仍为环境骨架：前端占位页和后端health，尚无登录、问答或工单。

## 首次启动

安装并启动Docker Desktop的Linux引擎。在项目根打开PowerShell执行：

```powershell
powershell -ExecutionPolicy Bypass -File infra/start.ps1
```

脚本构建并等待服务就绪。浏览器打开 http://127.0.0.1:5173 ，通过页面链接访问 /api/v1/health；后端直连 http://127.0.0.1:8000/api/v1/health 。首次构建需要镜像仓库/npm/PyPI网络，后续未改变依赖时启动无需重新安装依赖。

```powershell
docker compose ps
docker compose logs --tail 100
docker compose exec frontend node --version
docker compose exec frontend npm --version
docker compose exec backend python --version
docker compose exec frontend npm run build
docker compose exec backend python -m pytest
docker compose stop
docker compose start
docker compose down
```

目前没有业务测试，pytest收集不到测试不等于业务验收通过。Node24.14.1/npm11.11.0/Python3.12.12由镜像提供，成员无需安装宿主Python/Node。前端src/index/vite配置/tsconfig挂载供编辑，依赖留在镜像；新增public目录使用前应补挂载或重建。后端源码挂载，依赖在镜像中。改锁文件必须重建。普通停止禁止加-v，避免误删数据卷。

## 可选数据库

数据库仅为V1预备设施，不表示V1已放行。复制.env.example为.env，填写不同非空本地密码，不提交.env。执行：

```powershell
powershell -ExecutionPolicy Bypass -File infra/start.ps1 -Database
```

脚本先验证口令，绕过脚本启动时容器也会拒绝空口令。MySQL仅在Compose网络可见，地址db:3306，数据库campus_qa，用户campus_app；后端尚未接入数据库或迁移。mysql_data命名卷保存数据。已有卷的密码不会因编辑.env自动改变，须用旧凭据执行受控账号修改并同步配置，不能为改密码删除卷。

## 团队交付

分享项目文件时包含Dockerfile、compose.yaml、前后端锁文件及文档；不含.env、node_modules、.venv或数据库数据。离线分发可在已验证机器docker save两个应用镜像并由组员docker load，再使用docker compose up -d --no-build；数据库镜像需另行分发。不要把个人运行中容器当作环境基线。

环境配置与镜像改动见[环境变更与升级流程](环境变更与升级流程.md)。实际验证结果见证据目录，阶段签署仍由真实成员完成。
## 新成员前提与平台范围

已验证平台为Windows宿主＋Docker Desktop Linux/amd64容器。Mac/ARM尚未验证，不能承诺直接可用；镜像digest是否为多平台索引需检查manifest并在目标平台构建。不要仅依据digest字符串推断平台。ARM仿真amd64也需要单独验收。

启动前确认Docker Desktop显示Linux引擎Running；5173/8000未被其他服务占用；项目所在目录可被Docker绑定挂载（Windows/WSL或Mac共享目录设置）。权限拒绝、共享盘未授权、网络不可达均需先处理。宿主打开Docker界面不代表引擎已经就绪。

## 镜像下载与离线交付

不能假定其他成员继承作者机器的Docker镜像源。先执行docker pull对应基础镜像测试连接。受限网络可使用组织认可的镜像加速或代理，在Docker Desktop的Docker Engine设置中配置并应用；不要覆盖已有配置，也不要从仓库分发个人daemon.json、代理口令或未经信任的第三方镜像源。加速可用性不是项目保证，digest仍须匹配。

联网机器在构建成功后导出（项目根PowerShell）：

```powershell
docker save -o campus-qa-env-0.2.tar campus-qa-frontend:env-0.2 campus-qa-backend:env-0.2 mysql:8.4.4
Get-FileHash campus-qa-env-0.2.tar -Algorithm SHA256
```

连同项目源码及单独传递的校验值交给成员；tar不会提交Git，不包含运行中数据库卷或.env。接收方核对SHA256后执行：

```powershell
docker load -i campus-qa-env-0.2.tar
docker compose up -d --no-build --pull never --wait
```

离线启动不要使用默认start.ps1，因为它含--build。可选数据库还需填.env，并执行docker compose --profile database up -d --no-build --pull never --wait；若导入后digest引用不能解析，用docker image inspect核对导入镜像并在本地覆盖配置引用已核对的镜像ID，不忽略错误直接换任意镜像。

## 编辑与测试常见问题

前端顶层新增文件一律检查挂载：src内修改自动可见；public、env.d.ts、postcss配置等新路径须补Compose挂载或重建镜像，不能假定整个工程已挂载。依赖变更必须重建。后端当前使用Uvicorn StatReload，扫描.py变化，不依赖watchfiles；无watchfiles时WATCHFILES_FORCE_POLLING不起作用，已删除该无效环境变量。新增非Python资源需要重启服务或后续引入明确的监听器。

pytest当前没有业务测试，exit 5表示未收集到测试，并非容器损坏，不可作为测试通过。成员仍需新增真实测试。

快照校验：在项目根运行python infra/verify_snapshot.py；或使用后端容器运行挂载的同一脚本。脚本按UTF-8读取，兼容清单正反斜杠。跨平台Git换行转换可能改变文件字节；项目.gitattributes固定文本LF，不在校验时隐藏真实差异。

当前只有作者机器验证；另一台成员机器从干净checkout启动仍需独立证据，不删除现有镜像和数据卷冒充独立验证。
