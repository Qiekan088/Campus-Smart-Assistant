# 环境变更与升级流程

1. 说明变更原因、影响角色、旧新版本及回退方法；更新任务与ENV版本，不在运行容器里临时安装后当作团队交付。
2. 前端由A修改package.json，使用npm11.11.0更新package-lock.json；审查npm audit。后端由B汇总C/D需求修改requirements.in，在与Dockerfile相同的Linux Python容器使用pip-tools7.5.2运行pip-compile --generate-hashes --output-file requirements.txt requirements.in，提交输入及完整锁文件。不要手写传递依赖hash。
3. 更新基础镜像先拉取具体标签，读取RepoDigests并将验证的digest写入Dockerfile/Compose。不得捏造digest。多架构成员需要各平台实际构建，不将本机amd64验证推及所有平台。
4. 运行docker compose build，再docker compose up -d --wait；验证版本、前端build、直连与代理health。改源码无需重建依赖，改依赖必须重建并重建容器。
5. 数据库升级前独立备份，按MySQL支持的升级路径测试；Alembic迁移单次运行，禁止多个Worker同时迁移。降级镜像不代表可降级数据库格式，不直接回挂新格式卷到旧版本。
6. 记录命令、结果、失败和复验，生成文件哈希快照；另一真实成员审查。Git提交/远端操作按项目授权执行，本次不自动提交或推送。

## 回退

应用回退到上一组Dockerfile、Compose、依赖及锁文件再构建；保留数据卷。迁移回退按对应方案，不能自动清库。前端镜像依赖不依赖旧node_modules卷，因此不会被遗留卷遮蔽。旧frontend_modules卷若存在可先保留，当前配置不使用它。

### 可执行的后端锁定命令
在项目根PowerShell执行（基础镜像digest以Dockerfile当前值为准）：

```powershell
docker run --rm --mount "type=bind,source=$($PWD.Path)/app/backend,target=/work" -w /work python:3.12.12-slim-bookworm@sha256:593bd06efe90efa80dc4eee3948be7c0fde4134606dd40d8dd8dbcade98e669c sh -c 'pip install pip-tools==7.5.2 && pip-compile --generate-hashes --output-file requirements.txt requirements.in'
```
当前镜像在linux/amd64实测；backend仅提供健康检查。SESSION_TTL_SECONDS和REQUEST_TIMEOUT_SECONDS目前只是预留配置，不能声称登录过期或问答超时功能已实现。
