# 协商、任务、测试与验收记录模板

本文件将教师操作指引模板用于本项目；按实际活动填写，空白不是已经执行。记录可集中到对应文档，不要求每条都生成小文件。编号唯一；没有真实提交号时用实际快照标识。

## Q与ADR

Q：编号/问句；发问人和接收人；需求/接口依据；不确定或冲突；备选和代价；阻塞及可继续任务；最终可检验规则；实际确认人/角色/日期及出处；影响需求/架构/接口/数据/测试；正常/边界/异常预期；状态；同步位置与另一成员复核。已决定未同步不得关闭。

ADR：编号/标题；提议/待验证/接受/拒绝/暂缓/被替代；关联Q、需求和限制；可行备选；决定及理由/代价；验证方法/结果位置；实际确认与复核；重新评估条件；替代关系。不把技术建议自动写成已接受。

## 接口记录

编号/契约版本/所属阶段；需求、规则、权限、状态及ADR；提供方/调用方；HTTP方法路径或内部签名/事件名称；请求字段类型、必填、范围、空值；成功和失败响应schema/示例、错误语义和数据变化；前置后置；版本校验、幂等与竞争；事务/外部副作用；超时重试取消；隐私与禁记日志；查询分页排序过滤；TC关联；双方确认、复核及变更兼容方式。

## 本地任务卡

任务号TASK-版本-角色-序号；目标及可观察结果；负责人/另一成员审查人；输入基线；关联需求/Q/ADR/接口/TC；允许/禁止修改；前置依赖；权限事务幂等；计划与风险；必执行测试；完成标准（代码、证据、文档、人工审查）；需协商的停止条件；实际成员批准出处；状态及交接问句。

可以将同版四人的小任务集中在tasks/V0.md等当版文件；使用前把模板实例化，不为后三版预生成空任务。当前初始化未批准任何代码任务。

## 测试与问题记录

TC编号、关联需求规则及预期依据；层级；场景风险；前置角色和合成数据；操作/输入；预期输出、数据后态和不得发生变化；实际预期确认人/日期；执行环境、代码/数据版本、命令、时间、原始结果位置；实际观察；未执行/通过/失败/阻塞；问题号。

缺陷：编号；发现TC/证据；复现输入与前态；预期/实际；影响与责任模块；实现/测试/需求判责；处理决定及理由；修改位置；复验及关联回归；实际检查者；关闭或剩余影响。测试预期错误不能无依据改为代码现状。

## 审查及阶段验收

任务审查：实现者/实际审查者；diff或变更清单；需求契约、授权/事务/并发检查；测试和证据；文档同步；问题及整改；通过/需修改/待核验。

阶段验收单：记录ID；V0/V1/V2/V3；范围/环境/同一基线快照及文件清单；完成与缺项；主流程及关键异常；自动测试和实际成员观察；前版回归；Q/ADR/接口变化；残余风险和下一阶段阻塞。

## 证据与AI关键交互

证据E编号；类型；任务/需求/TC；代码和数据版本；真实原件相对路径、关键位置、日期、执行/审查者；证明范围及限制。关键AI交互保留输入版本、实际提示和关键输出、真实质疑/追问、修改、独立检查及最终采纳，不补造截图、真人意见或已完成调用。不要提交密钥、私人记录或整套缓存。
