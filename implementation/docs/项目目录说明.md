# 项目目录说明

本次依据现有共同约定、架构讨论稿、接口责任清单及四份角色Skill建立目录占位。项目工程根为 implementation/。目前只有目录和文档，没有程序、依赖清单、迁移脚本或可运行服务；目录建立不表示V0完成，也不改变现有Q/ADR和阶段验收状态。

## 使用边界

- frontend、backend/knowledge、backend/worker、backend/qa沿用现有文档路径；其他子目录是组织建议，可在V0评审时调整，不构成已确认的架构决策。
- backend为一个共享工程，knowledge与qa不是独立网络服务；worker可作为独立进程运行，具体机制仍待确认。
- models和迁移由B集中维护，C/D提出字段需求；contracts由提供方和调用方共同确认，不另建重复的数据模型或权限规则。
- frontend/tests与backend/tests存模块测试；根tests存跨模块验证；evidence存实际执行证据，两者用途不同。当前均未生成测试代码或执行结果。
- 后续按阶段任务逐步增加文件；预留工单相关位置不表示允许提前实施V2。
- 上传文件、检索索引和日志的运行时位置待设计确认；本次不创建存储服务，不预选向量库、任务队列或模型供应商。
- 沿用docs作为文档目录，不再建立重复的documents。架构基线版仍按现有约定在Q/ADR评审后形成，本次不伪造基线文件。
- 空目录不会被Git单独保存。本次未添加占位代码；若需要通过Git传递目录，可在后续加入模块说明或占位文件。
