# 项目背景与共同约定

## 产品与限制

课程题目为“智能客服或校园事务问答系统”，本组采用“校园事务问答与咨询工单系统”。以公开办事指南支持问答，保留来源、适用条件和历史依据；无法可靠回答时转异步人工工单。用户、知识维护、人工客服为主要角色；角色可兼任，权限仍分开。

核心闭环：上传资料→解析与预览→检查发布→检索与依据问答→未解决转工单→客服回复→用户确认。反馈只形成维护线索，修订仍走知识发布。系统不替学校作资格审批、材料真实性认定或费用结算；不默认接入真实校务系统及学校SSO。

经费有限，采用小规模可实现方案，不要求自部署大模型、微调或复杂集群。技术方向为Vue3/TypeScript/Vite/Element Plus，Python/FastAPI/SQLAlchemy/Alembic，MySQL；向量库、重排、Worker具体技术及依赖版本需Q/ADR评审。模块化单体为讨论方向，耗时资料任务由独立Worker进程处理，可共用后端代码。

## 四人技术责任

| 成员 | 维护范围 | 必须协商的边界 |
|---|---|---|
| A | frontend/：页面、路由、会话状态、接口客户端、流式展示、引用、上传预览和工单台 | B的HTTP接口；D输出事件经B转发到浏览器的格式 |
| B | backend/业务入口、鉴权、会话、ORM和迁移、知识发布、问答保存、工单与反馈 | C的任务/索引通知、D的编排调用与最终保存；共享Python依赖汇总 |
| C | backend/knowledge/、backend/worker/及自身测试：解析、分块、索引、检索、任务执行 | B持久化模型/发布事件；D检索结果、缺条件、版本信息 |
| D | backend/qa/及自身测试：澄清、模型适配、上下文、核验、生成与降级 | C候选契约、B最终提交与会话模式、A流式呈现 |

上述代码路径为初始组织建议，在V0共同确认。B集中维护ORM/迁移，C提出任务表和索引元数据要求，D提出问答记录要求；共同确认后由B落迁移，不让多套表定义各自演进。各人维护自己的依赖建议和启动信息，B汇总后端依赖不代表承担C/D代码。

组长/基线维护人从实际成员中指定，现未指定，不自动把全部公共文档归B或D。共享文档按责任章节编辑，交叉协议由调用方与提供方一起确认。

## 接口、协商与权限

有无法确定的内容，可以找其他负责的成员协商，输出问句就行。问句写给明确成员，附背景、接口或规则号、冲突、选项及影响；不发送外部消息，交给实际同学转达。只暂停依赖该结论的本版任务。格式示例：

> 向B、D确认Q-DEV-02：停用资料后检索索引可能延迟更新，最终提交由B怎样核验？若失败，D返回什么结果、A怎样结束展示？请确认事件和错误语义。

接口可以随实际情况变动；提议→双方确认→同步契约/样例/调用与测试→交叉复核。破坏性变更说明兼容或成套升级方案。未回复不等于接受。当前阶段之外的变更只记录，不借此提前开发下一版。

## 局域网范围

当前只做同一局域网内开发与联调，服务器、公网、云服务、域名、备份运维及CI暂不分配。每人维护自己的模块测试和本机启动信息。局域网功能需访问方能连接到指定开发机，提供方记录可配置监听地址与端口；浏览器中的localhost是浏览器所在电脑，不是另一位同学的电脑。

建议浏览器经A的开发代理访问B，B按约定调用同机Python模块或已确认内部接口，不要求C/D各自暴露公网服务。具体拓扑、跨域允许来源、Cookie/会话及流式代理在V0确认。MySQL仅对需要的后端/Worker连接开放；密钥只在持有者后端本地配置，不写入前端、示例配置或证据。未经同意不改系统防火墙、不开放无关端口。

## 文档与验证

原教师指引保持原文，用当前阶段需要的Q、ADR、接口、任务、测试、审查和验收模板落实。真实成员负责最终业务判断与全员阶段验收，AI只能协助；AI检查不替代另一成员的审查。全员门槛是用户新增强制约定。

历史需求报告仅为候选参考，不继承其旧章节分工、固定澄清轮次、时间精度参数、原型实现和通过结论。实际需求由八章工作稿及本轮已确认变更维护。当前建立初始化文档，不表示课程所有材料或部署验收已完成；后续若恢复部署范围需单独安排。
