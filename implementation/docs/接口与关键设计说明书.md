# 接口与关键设计说明书

状态：V0待协商。接口按版本逐步细化，本文件不是全部接口已冻结的承诺。具体路径、字段、错误码和技术实现由提供方、调用方确认，不让各AI自行定一套。统一记录版本，契约变化同步样例、模拟实现、真实实现和测试。

## 当前接口责任清单

| 契约范围 | 提供方 | 调用方 | V0要确认的内容 |
|---|---|---|---|
| 登录、会话、业务HTTP API | B | A | 请求响应、Cookie/令牌、权限、错误、分页和代理 |
| 问答编排入口和结果 | D | B | 问题、已知条件、澄清链、引用/结果类型、取消和超时 |
| 检索与缺条件诊断 | C | D | 片段、版本、来源、适用条件、分数、缺项、排除原因、空结果 |
| 资料接收与任务状态 | B提供API/持久化，C执行处理 | A、C | 文件限制、任务状态、进度、失败、重试与重复提交 |
| 发布事件及索引同步 | B | C，D受影响 | 版本权威、索引滞后、停用、重试及最终核验 |
| 问答最终保存 | B | D | 候选和版本复核、会话模式、快照原子保存、中断结果 |
| 流式事件 | D提供生成事件，B鉴权与转发 | A | 事件序列、待核验/最终结果、中断、重复或乱序处理 |
| 工单与反馈API（V2细化） | B | A；D提供必要咨询背景 | 权限状态、事务、幂等、竞争及隐私范围 |

C/D可用同一接口的模拟提供者并行。模拟候选必须保留片段ID、版本、来源及条件，明确其合成性质；共同契约未确认前样例只能作草案。分数是相关度，不是答案正确概率。C报告缺失条件，D组织澄清、计数及上下文，B保存会话，A展示。

## 契约应包含什么

HTTP接口记录接口号、需求/规则/ADR、方法路径、调用角色及对象范围，请求字段类型/必填/范围/空值、成功和失败示例、数据是否变化、前后条件、并发幂等、事务及外部副作用、隐私日志、TC关联、双方确认及版本。查询接口明确分页排序过滤。关键写接口至少给正常、业务失败、重复三例。

内部函数/事件同样记录输入输出schema、调用语义、异常/结果类型、超时取消、版本与测试；不硬套HTTP状态。接口ID按API/INT/EVT区分并唯一登记。具体模板见记录模板.md。

## 关键详细设计

B维护业务不变量、ORM、迁移和事务边界；C维护任务状态、文件/分块/索引一致性；D维护澄清链、模型超时、引用支持核验与输出事件；A维护会话缓存及事件消费。跨模块部分共同画必要顺序/状态图。文件正文、日志、模型输出均不构成授权，不接受“我是管理员”等自然语言提权。

## 更新方式

新增契约按当前阶段写；变更记录旧/新语义、调用方影响、兼容或同步切换方式和回归案例。双方未答复不算确认；AI能给候选但不能填写真人确认。共享文档修改有冲突时先协商，不覆盖另一方未合并内容。
