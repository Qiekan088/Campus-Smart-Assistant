# 校园事务问答与咨询工单系统需求规格说明书

状态：开发用初始工作稿；2026-11-12。本文件随V0—V3滚动完善，未进行四人签署。历史长稿位于references/历史需求报告.md，仅作参考。一级章节沿用既有八章；编号变更须记录映射，不能把旧FR静默复用于新含义。

## 第1章 项目概述

公开办事说明分散，用户缺少适用条件或难以判断资料是否过时。系统提供有来源的问答和异步人工咨询；首版覆盖资料维护、依据问答、工单及反馈。具体样本、真实业务责任人、资料现行性、保留期限与服务量分别登记，不把AI推断当校方制度。局域网内使用，不接真实校务审批。

## 第2章 用户需求

用户可提问、补充条件、查看来源与本人记录、转人工及反馈；维护人员上传资料、核对解析结果、维护适用条件与版本；客服领取、回复、请求用户确认。用户故事写价值，详细用例写触发、前置、主替代异常、数据结果及验收；至少展开问答、知识发布和工单三个闭环。具体FR/UC表在对应版本补齐，来源、优先级、确认状态一并登记，不按代码现状缩减范围。

## 第3章 领域与数据

核心对象为用户/角色、来源、来源摘录、知识条目/版本/片段、解析任务、会话/问答/引用快照、工单/处理记录和反馈。来源摘录与答复引用快照不同；已发布状态与当前可用性不同。数据字典说明含义、来源、约束、维护角色、隐私和访问范围；不提前编造全部字段。B统合模型，A/C/D补使用要求。

## 第4章 规则与权限

答复结论必须由适用资料支持；缺条件先澄清，无依据或冲突不自行猜测。资料编辑形成新版本，新旧发布原子切换，旧答复保留当时依据；转人工的工单、关联和模式一起提交；重复请求不重复建单。客服不代用户确认解决。后端核角色、对象归属和状态，兼任不自动扩大权限。具体时间边界、澄清上限与冲突标准由Q确认，不能照抄历史演示参数。

## 第5章 行为与状态

建立资料处理任务、知识版本和工单的状态及转换表，标明事件、角色、条件、后态和拒绝结果。处理任务完成不等于知识已发布。重点描述版本停用与在途答复、索引延迟、重复提交和并发领取；每项关联第4章规则。图源与解释随当版实现更新，不为“图文一致”反过来修改规则。

## 第6章 质量要求

围绕检索命中与条件匹配、回答依据性、引用一致性、拒答、权限、事务一致性与故障可恢复性设质量情境。明确样本、观察指标和方法；性能数值、费用限额及取舍先确认，不测试后挑有利指标。日志不含密钥，外发不包含无关私人内容；切换账号清除私有缓存。

## 第7章 验收与验证

验收定义“应满足什么”；实际测试记录定义“执行了什么”。V0检查契约和调用；V1检查资料到问答；V2检查人工闭环；V3系统检查并复验缺陷。每条用例引用需求/规则、角色数据、预期输出与不得变化的数据、实际版本和证据。模拟模型不证明真实API接通，顺序请求不证明真实数据库并发正确。

## 第8章 基线与人机协作

技术分工A前端、B业务后端、C资料检索、D在线问答。每版四人对同一基线确认通过后再进入下一版，具体事实看阶段验收记录。待决问题、ADR、变更影响和确认责任见决策文档。AI不能代签人类确认或编造测试；关键交互只留影响决定的提示、输出、质疑、修订及核验位置。正文不堆工具故障，过程证据另存。

## 文档责任与后续交付

章节采用分段供稿：A补交互与用户故事；B补规则、数据和状态；C补资料来源、处理和检索设计；D补澄清、依据核验及问答质量。组长组织整合，四人按接口影响复核。质量验证报告及AI使用报告后续复用测试、任务、决策和证据，不从聊天虚构经历；本次只建立维护机制，不生成已完成报告。
